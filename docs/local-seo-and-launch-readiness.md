> Haribol Lubes Limited supplies automotive, industrial and specialty lubricants from Mlolongo, Kenya, including the Mastermax lubricant range.

This description avoids unsupported leadership, scale, age, customer, delivery, and performance claims.

## Cannibalization and page roles

- Homepage: company-level supplier/entity intent for Kenya.
- Products index: searchable catalogue and product-discovery intent.
- Categories: one product-family intent each.
- Industries: operating and procurement context rather than product-family definitions.
- Product Finder: guided selection intent; configured states stay noindex.
- Insights: informational/editorial intent.
- About and Contact: entity and verified-location intent.

Titles, H1s, copy, and internal relationships preserve those roles. Category and industry pages already contain useful, distinct data-driven content, so no new SEO landing page is justified. City pages for Nairobi, Mombasa, Kisumu, Nakuru, or other locations are rejected as unsupported doorway pages. Fourteen application routes are also rejected: the application descriptions are catalogue-derived and too brief for standalone pages. Applications remain valuable inside categories, industries, and Product Finder.

The homepage “Specialty” pillar remains a business/product grouping. A dedicated `/specialty` page would be thin today. Cutting oil and mould-release oil remain within existing industrial/specialty catalogue relationships; grease already has a strong canonical category.

## Production deployment prerequisites

Run `pnpm check:production` against the intended production environment before deployment. It fails closed when required configuration is missing or unsafe.

- Set `NEXT_PUBLIC_SITE_URL=https://haribollubesltd.co.ke`.
- Set `SEO_INDEXING_MODE=production` only at the final approved launch step. Preview/staging must omit it or use `staging`.
- Provision managed PostgreSQL with SSL, connection pooling appropriate to the host, automated backups, least-privilege application credentials, and a documented restore test.
- Apply committed Payload migrations in a release step before serving the new application. Do not use development schema push in production.
- Set a unique high-entropy `PAYLOAD_SECRET` and store all secrets in the hosting secret manager.
- Use `CATALOGUE_DATA_SOURCE=cms` and `RFQ_REPOSITORY=payload` after migration and production-data verification.
- Move Payload media to Cloudflare R2 or an equivalent object store. Configure private credentials, CORS if needed, a deliberate public/private URL policy, media backup, and lifecycle rules. Local filesystem media is not production-safe.
- Configure Postmark, Resend, or another approved transactional provider. Verify the sending domain and sender; set the provider credential and `EMAIL_FROM`.
- Keep `info@mastermax.co.ke` only as the current approved RFQ destination. A future sender such as `website@haribollubesltd.co.ke` or `enquiries@haribollubesltd.co.ke` is an example requiring domain ownership and verification; sender and destination are separate decisions.
- Configure automated PostgreSQL and object-storage backups and test restoration before launch.

The site can launch as a catalogue and enquiry site with commerce disabled. Ecommerce activation, offers, cart, checkout, payments, taxes, and order operations remain a separate capability.

## Security, admin, API, and operations

The application now returns `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, a restrictive camera/microphone/geolocation `Permissions-Policy`, and `X-Frame-Options: SAMEORIGIN`. Admin and API responses also receive `X-Robots-Tag: noindex, nofollow`.

Do not add an untested global Content Security Policy because Payload Admin and Next.js assets require a deliberate directive inventory. Add CSP in a dedicated security phase with report-only observation first. Enable HSTS at the production edge only after HTTPS and subdomain behavior are verified; do not preload prematurely.

Payload Admin requires authentication and collection access controls protect records. Production hardening should include strong unique admin credentials, least-privilege roles, login rate limiting at the edge, secure session/cookie verification, and MFA only if the chosen identity architecture supports it. IP or VPN restrictions are optional operational controls.

GraphQL is disabled. Payload REST endpoints remain because server/CMS architecture uses them, with collection-level access rules. RFQ is an intentional public write endpoint with validation, size, timing, honeypot, idempotency, and rate-limit behavior. Storefront test endpoints remain 404 unless explicit test mode is enabled and must never be enabled in production.

`/api/health` returns only `{ "status": "ok" }`, sets `Cache-Control: no-store`, and discloses no database, build, secret, or stack information. Public errors return bounded messages; server logs avoid request bodies and secrets. Add monitoring later for frontend/runtime errors, server failures, RFQ persistence/delivery, CMS failures, and future payment failures. Sentry is not installed in this phase.

- Verify products, decide which details can publish, approve packshots and technical documents.

### Platform and operations

- Provision PostgreSQL, object storage, email delivery, backups, secrets, and restore procedures.
- Run migrations and seed/review production data without development credentials.
- Validate RFQ storage and real email delivery using controlled test data.
- Confirm admin authentication, roles, rate limiting, and production test-mode flags are off.
- Configure runtime/error monitoring in a later approved phase.

### Domain and search

- Configure DNS and TLS for `haribollubesltd.co.ke`.
- Permanently redirect HTTP to HTTPS and www to the non-www host in one hop.
- Run the production environment checker and production crawl.
- Confirm robots, sitemap, canonical, schema, 404, security headers, and `SEO_INDEXING_MODE=production`.
- After deployment, create the Search Console domain property, verify by DNS, submit `/sitemap.xml`, inspect the homepage/categories/approved Insight, request indexing selectively, and monitor Pages, Core Web Vitals, and Enhancements.
- Create/claim GBP only with the completed business profile inputs.
- Add analytics later only after the tracking/cookie decision is approved.
